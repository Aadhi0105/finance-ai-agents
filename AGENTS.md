# Keystone development preference

During Keystone implementation work, always open the local live preview beside
the chat and keep it updated as the work develops. The user wants to watch the
implementation. Use an isolated fictional demonstration workspace when exercising
new workflows, and preserve existing user reports and inputs.

# Agreed development sequence

The user explicitly prioritised this order on 11 November 2026: complete all
six document/PDF intake parts, then begin the broader backend enhancement
programme immediately afterwards. Preserve this order unless the user changes
it. Backend work needed to deliver intake belongs within the intake parts;
the broader programme builds on those completed capabilities.

See [the post-intake backend roadmap](docs/webapp/post-intake-backend-roadmap.md)
for the retained scope and sequencing decision.
